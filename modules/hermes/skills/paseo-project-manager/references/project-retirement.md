# 项目退场与磁盘清理

用户明确要求退场后，核实项目 ID、协调者 ID、主工作区 ID 和涉及路径。分别记录已授权的工作区归档、项目登记移除和主目录删除范围。

## 协调者完成项目内部收尾

1. 核对项目的实际布局。协调者通常驻 `develop` 的普通本地主工作区，其他开发工作区通常是 Paseo 托管 worktree。以登记的 `rootPath`、`cwd`、`worktreeRoot` 和 `isPaseoOwnedWorktree` 为准。出现普通开发工作区或共享目录时，单独报告其归属和处置方案。
2. Project Manager 通知协调者完成并核验 Git 收尾，包括协调者自己所在的分支。协调者等在途任务结束并检查各工作树，处理未提交和暂存修改、未跟踪文件、stash、需保留的忽略文件、detached HEAD 及子模块修改。协调者将应保留的提交推送到经用户授权的远端，并核验目标分支包含这些提交。没有远端时，协调者按用户确认的方式保留并验证独立副本。保存在待删主仓内的 Git 提交不能作为恢复依据。
3. 协调者可用 `archive_agent` 归档本项目内除自己以外的 Agent，包括与自己同工作区的其他 Agent。用 `archive_workspace` 归档本项目内已收尾且纳入授权范围的其他工作区，保留自身所在的工作区交给 Project Manager。逐项核对 `projectId`、目标 `agentId` 或 `workspaceId`。Paseo 可能随工作区归档移除托管 worktree，归档授权须覆盖这个清理效果。协调者核对 `removedDirectory` 和实际路径，确认共享引用、失败或残留项，并处理项目内部剩余项。

## Project Manager 归档 Paseo 记录

1. 等待协调者确认「已收尾，可以归档」。这项确认涵盖协调者已完成的提交、推送和核验。收到确认后进入 Paseo 归档检查。协调者报告阻塞时，保留其会话和工作区，让它继续收尾。
2. 确认协调者是直属子代理且已无活动下级，工作区归档只影响授权范围内的对象。通过 `archive_agent` 归档直属协调者，再通过 `archive_workspace` 归档其普通主工作区。回查两者均已归档。普通主工作区的磁盘目录由此保留。
3. 用户要求整个项目退场并且没有剩余活动工作区时，用 `archive_project` 归档该项目，之后用 `list_projects` 回查 `archivedAt`。项目仍有活动工作区时，交回协调者处理。
4. 确认项目已归档后，保留 `AGENT.md` 中的那一行，阶段记为「已归档」。主目录仍在时，单独记录清理状态，即可结束 Paseo 归档。

## Project Manager 清理主目录

只有以下条件全部满足，才执行磁盘删除：

1. **归档已完成。** 已回查协调者会话及其普通主工作区都已归档。
2. **用户已确认删除具体路径。** 使用实际绝对路径核对项目根目录与协调者的工作目录。同一路径只处理一次。归档授权本身只覆盖归档，已明确授权的删除路径无需重复确认。
3. **收尾确认仍有效，目录已停用。** 以协调者的收尾确认作为内容可恢复的依据。检查目录在收尾后是否又被使用或改动，以及是否仍有其他项目或 worktree 依赖该路径。发现后续改动时，安排协调者重新收尾。检查目标仍是已确认的普通目录，实际路径发生变化时暂停。
4. **权限和结果可核查。** Project Manager 从目标目录外调用 delete_archived_project_directory，传已归档的 project ID 和用户确认的精确绝对路径。Paseo 会就这一路径再显示一次性操作批准。删除后确认路径已不存在。未获批准或操作受阻时，记录原因与路径并保留剩余目录。

## 登记磁盘清理状态

在 `AGENT.md` 的项目行保留项目 ID、主工作区 ID、协调者 ID 和已归档阶段。进度摘要写协调者的收尾确认或具体阻塞。清理信息使用以下列，多个待清理路径逐一列出。

| 列 | 记录内容 |
| --- | --- |
| 磁盘清理状态 | `未安排`、`待确认清理`、`已确认待执行`、`明确保留` 或 `已删除`。仅在所有已确认路径均核实移除后写 `已删除`。 |
| 待清理绝对路径 | 仍存在且待处置的准确目录。部分已删除时只保留剩余路径。 |
| 待确认起始时间 | 首次进入 `待确认清理` 的时间。普通查询和提醒不会刷新它。 |
| 上次清理提醒时间 | 上一次实际向用户提醒的时间。 |

旧表按原样保留项目行并补列。未核实的清理信息填「—」。只有核实磁盘目录仍在且确实等待用户决定时，才标成 `待确认清理`。

待确认满 14 天后，在后续项目管理会话的答复末尾合并提醒到期项目，列出项目名与路径。距离上次提醒至少 14 天再提醒一次。用户明确保留时改为 `明确保留` 并停止提醒。提醒不视作清理授权，也不改变项目的最后活跃时间。
