# 项目退场核验与执行顺序

进入条件为用户明确要求退场，且拟归档对象、项目根目录和操作范围均已确认。先清点关联工作区和会话 ID，再核对授权是否包含移除项目登记或删除物理目录。

## 确认分支和实际目录

- 项目通常由协调者驻 `develop` 的主工作区，开发工作区通常各有一个 Git worktree。协调者统筹项目各分支和各开发工作区的收尾，以实际 Git 和 Paseo 登记为准。
- 分别核对项目 `rootPath`、协调者工作区 `cwd` 和托管 `worktreeRoot`。同一路径只清理一次。若多个工作区引用同一个 worktree，先确认所有引用方都已完成退场。

## 什么时候可以删除磁盘文件

以下条件全部满足，才可删除普通目录，或调用会移除托管 worktree 的归档操作：

1. **用户已明确授权删除对应路径。** 核对项目 ID、工作区 ID 和实际绝对路径。仅有 Paseo 归档或移除登记的授权时，保留物理目录。用户已明确授权该路径时，沿用现有授权。
2. **本地应保留的内容可从外部恢复。** Git 项目逐个工作树核对，所有应保留的改动已提交并推送，重新查询远端确认目标分支包含对应 SHA。未跟踪文件、stash、需保留的忽略文件等也须清点并落实去向。无 Git 远端的项目先按用户确认的方式做备份，验证备份可恢复后才可删除。
3. **目标目录无人继续使用。** 相关 Agent、终端任务和写入进程已停止工作，其他工作区或项目没有依赖该路径。删除前协调者再查一次，确认核验后没有新增修改，且路径和归属仍与授权一致。
4. **退场证据已核验。** 协调者提交远程地址、分支和 SHA，或可恢复备份的位置，以及路径和剩余项。Project Manager 核验项目根目录与协调者工作区的清理条件，并按下节选定执行方。托管 worktree 由负责对应工作区的一方通过 Paseo 归档处理。

任一条件未满足时保留目录，报告具体缺项。删除完成后核对路径确已移除，再据实更新项目登记册。

## 保留远程可恢复的结果

- 协调者先让在途任务结束并汇总全部项目工作区及 Git worktree，包括主工作树、其他分支和 detached HEAD。检查未提交、暂存、未跟踪文件、stash，以及必须保留的忽略文件。项目用到子模块时，也核对其中的本地修改和提交。未保存内容经收尾处理后才可回收目录。
- 应保留的修改提交并推送到用户授权的远程和分支。核验从远程重新取得的分支包含所需提交。回报远程地址、分支和提交 SHA。若需要保留远程尚未包含的提交、没有远程、无法核验远程或项目本身不是 Git 仓库，先暂停目录删除，等用户确认归档或备份方式。
- Project Manager 核验协调者的报告是否覆盖每个工作树、远程分支和应保留的提交。发现缺项就交回协调者补核。Git 提交、推送和项目内部清理由协调者负责。Project Manager 跟进项目根目录和协调者工作区的最终清理。

## 归档和清理

1. **先完成项目内部退场。** 由协调者收尾并归档它管理的 Agent、其他工作区和 worktree。Paseo 托管的 worktree 由协调者通过对应工作区归档来处理。若仍有工作树依赖主仓目录，先处理依赖，再清理主仓。协调者向 Project Manager 回报结果和剩余项。
2. **再处理项目根目录和协调者目录。** 删除条件全部满足后，优先由协调者清理经授权的普通目录。删除目录本身需要其父目录的写入和搜索权限，还要核对工具权限。先交接证据并完成需要原目录的操作，再从已核实的目录外执行，并回报删除结果。协调者无法删除目录或无法在删除后回报时，Project Manager 安排有权限的操作者从目录外执行，核对实际结果。当前 Project Manager 的 Hermes 文件工具没有删除目录的能力，普通本地目录也不会由 Paseo 归档自动移除。
3. **归档直属协调者及其工作区。** 核实协调者的 `paseo.parent-agent-id` 等于当前 Project Manager 会话 ID，并核对其 `workspaceId`。回查该会话无活动下级，且工作区归档只会影响授权范围内的对象。工作区里还有其他 Agent 或仍有下级未收尾时，交回协调者处理。核验通过后，对直属协调者调用 `archive_agent`，对它所在的工作区调用 `archive_workspace`。若该工作区本身是 Paseo 托管 worktree，预先核对回收范围，归档后检查 Paseo 的清理回执。
4. **移除项目登记。** 仅在用户已确认整个项目退场，且项目已无活动工作区时推进。当前 MCP 缺项目归档接口，请有权限的操作者通过 Paseo 界面或 `paseo project delete <project-id>` 完成并回查。项目删除会归档剩余活动工作区，发现剩余项时交还协调者收尾，完成后再移除登记。
5. 保留 `AGENT.md` 中的项目记录。确认整个项目已归档后标记为「已归档」，摘要记录已核验的远程分支和 SHA，以及本地目录处置结果。部分步骤失败时记录真实状态和待办。
